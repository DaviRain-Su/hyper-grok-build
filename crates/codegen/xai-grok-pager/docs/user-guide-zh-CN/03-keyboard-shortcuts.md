# 键盘快捷键

Grok Build TUI 中的按键绑定参考。绑定内置，目前无法重映射。

---

## 输入模式

Grok 有两种输入模式，控制如何在回滚区中导航：

- **Simple 模式**（默认）：方向键导航，`Shift+方向键` 按回合跳转，`Space` 聚焦提示区，任意字母键会自动聚焦提示区。
- **Vim 模式**（可选）：`j`/`k` 导航，`H`/`L` 按回合跳转，`J`/`K` 按回复跳转，`h`/`l` 折叠，`e`/`E` 展开/折叠，`i`/`Tab`/`Space` 聚焦提示区。

默认 Simple 模式。切换到 Vim：在 `~/.grok/config.toml` 的 `[ui]` 下设 `vim_mode = true`，或运行时用 `/vim-mode` 切换。详见 [配置](05-configuration.md)。

下表同时记录两种模式。「Key」列为 Vim 绑定，「Alt Key」列为 Simple 模式下的等价键（方向键等）。

> **需要 Vim 模式**：回滚区上下文中的单字母与 `Shift+字母` 绑定
> （`j/k`、`h/l`、`g/G`、`L/H`、`y/Y`、`o/O`、`r`、
> `x`、`e/E`，以及 `i` 插入模式替代）需要在 `~/.grok/config.toml` 中
> 设置 `[ui].vim_mode = true`（或用 `/vim-mode` 切换）。方向键、`Tab`、
> `Esc`、`Space`、`PageUp/Down` 以及所有 `Ctrl+字母` 快捷键在两种模式下均可用。

## 导航（焦点在回滚区）

在回滚窗格中移动对话条目。

| 键 | 替代键 | 操作 |
|----|--------|------|

| `⇧L` | `Shift+Right` | 跳到下一回合（用户提示） |
| `⇧H` | `Shift+Left` | 跳到上一回合（用户提示） |
| `⇧J` | | 跳到下一助手回复 |
| `⇧K` | | 跳到上一助手回复 |
| `g` | | 到回滚区顶部 |
| `⇧G` | | 到回滚区底部 |
| `Ctrl+K` | | 向上滚动一行（不改变选择） |
| `Ctrl+J` | | 向下滚动一行（不改变选择） |
| `PageUp` | | 向上翻一页（选择移到视口顶部） |

## 焦点

在提示输入与回滚窗格之间切换。

| 键 | 替代键 | 上下文 | 操作 |
|----|--------|--------|------|
| `Tab` | `Space`（Vim 模式下还有 `i`） | 焦点在回滚区 | 聚焦提示输入 |
| `Tab` | | 焦点在提示区 | 聚焦回滚区（Simple 与 Vim 均如此） |
| `Enter` | | 焦点在提示区 | 发送当前提示 |

**Esc 不是焦点键。** 它遵循下方的清空 / 回溯语义（并吞掉回合中途），与 `[ui].simple_mode`（提示编辑器）和 `[ui].vim_mode`（回滚导航）无关。浮层、模态、斜杠/文件下拉、语音、搜索与选择仍会优先占用 Esc。

## Escape

| 状态 | 手势 | 效果 |
|------|------|------|
| 回合进行中 | `Esc` | 吞掉，无操作（**不**取消）。用 `Ctrl+C`（或调色板 / 其他取消入口）。 |
| 回合取消中 | `Esc` | 重新发送取消（若首次确认丢失则重试）。此状态下 `Ctrl+C` 会升级为退出。 |
| 空闲 + 非空提示（文本或图片芯片），**焦点在提示区** | **800ms 内 2× `Esc`** | 清空提示；非空文本会保存到提示历史。第一次按显示「再按一次以清空」。 |
| 空闲 + 空提示 + 已有对话消息，**提示或回滚聚焦** | **800ms 内 2× `Esc`** | 打开回溯选择器（等同 `/rewind`）。第一次按静默（无 toast）。 |
| 空闲 + 空 + 无消息，**或**回滚聚焦且有草稿 / 模式化（`!` `#` 反馈）编辑器 / 待输入浮层 / 打开的历史搜索 | `Esc` | 吞掉，无操作（不聚焦回滚）。清空仅针对提示窗格；回溯需要空的 Normal 模式编辑器、无待处理浮层、无打开的历史搜索 —— 阅读回滚永远不会改动你的草稿、编辑器模式、待答问题或进行中的搜索。 |

**抢占 Esc（在回合中途吞掉 / 清空 / 回溯之前运行）：** 浮层、模态、斜杠/文件/补全下拉、历史搜索、回滚搜索、文本选择、链接高亮、语音，以及提示为空时的 **Bash / Remember / Feedback 模式退出**（Esc 离开 `!` / `#` / 反馈模式回到普通提示 —— 即使回合进行中）。

**Ctrl+C 与 Esc：** 回合进行中草稿非空时，Ctrl+C 清空草稿并保持回合；空提示上再按一次 Ctrl+C 才取消。Esc 不取消进行中的回合（仅在已在取消过程中时重试）。空闲非空时 Ctrl+C 一次清空；Esc 需 800ms 内按两次。

影响智能体会话的操作，在智能体屏幕上可用。

|----|--------|------|
| `Ctrl+P` | 智能体屏幕 | 打开命令调色板 |
| `?`（Shift+/） | 智能体屏幕 | 打开命令调色板（替代绑定） |
| `Ctrl+M` | 智能体屏幕 | 打开模型选择器 / 切换模型 |
| `Ctrl+M` | 焦点在提示区 | 切换多行输入模式 |
| `Ctrl+C` | 智能体屏幕 | 取消当前回合（或先清空非空草稿；见 Escape 表） |
| `Ctrl+O` | 智能体屏幕 | 切换始终批准（YOLO）模式 |
| `Ctrl+S` | 智能体屏幕 | 打开会话选择器（恢复先前会话） |
| `Ctrl+;`（替代：`Ctrl+'`） | 智能体屏幕 | 切换提示队列窗格（非空时）。**仅本地 macOS** VS Code 家族：主绑定 **`Ctrl+4`**（`;` / `'` 仍为替代）。SSH 与非 Mac 保持 **`Ctrl+;`** / **`Ctrl+'`**。 |
| `Shift+Tab` | 焦点在提示区 | 循环模式（Normal → Plan → Always-approve） |
| `Ctrl+B` | 智能体屏幕 | 将正在运行的前台命令送入后台 |
| `Ctrl+T` | 智能体屏幕 | 切换 todos 窗格 |
| `Ctrl+G` | 智能体屏幕（完整 TUI） | 切换 tasks 窗格 |
| `Ctrl+G` | 普通编辑器（minimal 模式） | 在外部编辑器中编辑当前草稿且不发送。若终端占用该组合键，从命令调色板选 **Edit Prompt in External Editor**。 |
| `Ctrl+L` | 智能体屏幕 | 打开扩展模态（**非 VS Code 家族**；在 VS Code / Cursor / Windsurf / Zed 上，`Ctrl+L` 是回合中途 **插话**，扩展通过 `/plugins` / `/hooks` 打开） |
| `↑` | 焦点在提示区（空提示、普通输入模式） | 打开历史面板并填入上次提示；`↑`/`↓` 在条目间移动（每项进入输入框），在最新项上 `↓` 关闭面板，输入可就地编辑召回的提示。召回的 `!` shell 命令会重新进入 shell 模式。`↓` 不会打开历史。 |
| `!` | 焦点在提示区 | 进入 shell 模式（在空提示上输入 `!`） |
| `Ctrl+.`（替代：`Ctrl+X`） | 智能体屏幕 | 打开键盘快捷键帮助 |
| `F2`（替代：`Ctrl+,` / `Cmd+,`） | 智能体屏幕 | 打开设置模态 |

**注意：** `Ctrl+M` 依赖上下文。提示聚焦时切换多行输入；否则打开模型选择器。

**注意：** Minimal 模式外部编辑依次解析 `$VISUAL`、`$EDITOR`，最后是 `vi`。值可含带引号参数。保存只替换草稿；空文件清空草稿。含粘贴/文件/图片芯片的草稿须在编辑器中改，以免附件被压扁。

**注意：** `Ctrl+'` 是 Windows 上 `Ctrl+;` 的替代 —— 部分 Windows 控制台会丢掉标点键上的 `Ctrl` 修饰。

**注意：** `Ctrl+.` 需要 Kitty 键盘协议（或 tmux `extended-keys on` 以便协议穿透）。在 VS Code / Cursor / Windsurf / Zed 集成终端、VTE、Apple Terminal、Windows Terminal、JetBrains、`extended-keys off` 的 tmux、screen 等无 KKP 环境中，Grok 会把 **`Ctrl+X`** 标为主快捷键速查键。**`Ctrl+X` 始终可用**，即使 `Ctrl+.` 不行。tmux 中修饰键异常时运行 `/doctor`。

## 图片粘贴与拖放

| 操作 | macOS | Linux | Windows |
|------|-------|-------|---------|
| 从文件管理器拖图片到提示区 | Finder ✓ | Files / Dolphin ✓ | Explorer ✓ |
| 在文件管理器复制文件后粘贴 | `Cmd+V` | `Ctrl+V` | `Ctrl+V` |
| 截图或「复制图片」到剪贴板后粘贴 | `Cmd+V` | `Ctrl+V` | **`Alt+V`** |

非图片文件会插入绝对路径文本，而不是芯片。

> **Windows 上的 `Alt+V`** 为 grok 专用。Windows Terminal 默认 `Ctrl+V` 只粘贴纯文本并静默丢弃图片剪贴板；`Alt+V` 绕过该拦截。若也要用 `Ctrl+V` 粘贴图片，在 Windows Terminal 的 `settings.json` 的 `actions` 中加入 `{ "command": null, "keys": "ctrl+v" }`。

### Linux PRIMARY 与 CLIPBOARD

Linux X11 有两套独立文本选择：

- `Ctrl+V` 读取 **CLIPBOARD**（显式复制/剪切），从不回退到 PRIMARY。用 `xclip` 写入：`printf %s "text" | xclip -selection clipboard`。
- 在 Grok 中未修饰的中键点击读取 **PRIMARY**（当前鼠标选择），仅当 `DISPLAY` 非空。纯 X11 可用原生读取回退；XWayland 需要 `PATH` 上有 `xclip` 或 `xsel`，以便 Grok 读 X11 选择而非 Wayland PRIMARY。按下处理一次；松开不会再次粘贴。
- `Shift+Insert` 是终端原生粘贴选中文本的方式。许多终端也用 `Shift+中键` 绕过应用鼠标报告。

通过 SSH 时，远程 Grok 进程通常无法访问终端本地的 X11 选择。请用终端原生的 `Shift+Insert` 或 `Shift+中键`，让本地终端把选中文本经 PTY 发送。

## 活动回合中（智能体运行时）

智能体生成时：

- **普通 `Enter`**（编辑器有文本）会把后续内容 **排队**。排队的后续在当前回合结束后运行 —— 当智能体被后台任务或子智能体阻塞时会故意 **保持**（提示会说明保持原因及如何立即发送）。
- **在已清空的编辑器上再按 `Enter`**（双 Enter）立即发送 **队首** 后续。
- **立即发送** 组合键是 **取消并发送**：停止当前回合（后台任务、子智能体与队列其余部分继续），并把你的消息作为下一回合发送，因此总出现在 transcript 底部：
  - **非空编辑器** → 取消并立即发送该文本。
  - **空编辑器** + 有排队后续 → 立即发送 **队首** 后续（无需聚焦队列窗格）。在队列窗格上，同一组合键（或 **[Send now]** 按钮）发送 **选中** 行。
  - **空闲**，或 **空编辑器且无排队** → 该键无操作。
- 智能体 **阻塞等待**（任务输出或子智能体）时，带文本的普通 `Enter` 也会立即送达 —— shell 取消被阻塞的回合并接着运行你的消息。

| 终端 | 主绑定 | 替代 | 操作 |
|------|--------|------|------|
| 默认 | `Ctrl+Enter` | `Ctrl+I` | 立即发送（取消当前回合，接着运行你的消息） |
| Apple Terminal | `Ctrl+O` | `Ctrl+Enter`、`Ctrl+I` | 立即发送 |
| VS Code 家族（VS Code、Cursor、Windsurf、Zed） | **`Ctrl+L`** | *（无）* | 立即发送（不用 `Ctrl+I` —— Tab / 宿主聊天；插件用 `/plugins`） |

在 `/multiline` 模式下，`Shift+Enter`（或 `Alt+Enter`）发送，普通 `Enter` 插入换行 —— 但回合中途 **空** 编辑器且有排队后续时，普通 `Enter` 仍会 **立即发送** 队首行（与普通模式相同）。（`Ctrl+Enter` 在非 VS Code 家族上绑定为回合中途立即发送；不会提交新的空闲回合。）

立即发送是故意打断的 —— 读作「停下手头的事，处理这个」。若要 **不** 停止智能体而递纸条，用普通 `Enter` 排队；智能体在下一回合边界拾取。

> **WezTerm**：这些带修饰的 Enter 需要在 WezTerm 配置中设 `enable_kitty_keyboard = true`。完整步骤与一行变通见 [终端支持指南](21-terminal-support.md#problem-ctrlenter-doesnt-interject-in-wezterm)。

> **Windows（非 VS Code 家族）**：部分控制台会丢掉 `Ctrl+Enter` 上的 `Ctrl` 修饰（可能塌成裸 `Enter` 或 `Ctrl+J`）。用 `Ctrl+I` 作替代 —— 字母键 Ctrl 组合到处都稳定。VS Code 家族请用 **`Ctrl+L`**。

> **VS Code 家族 `Ctrl+L`**：Grok 用它插话，扩展快捷键不绑定（用 `/plugins` 或命令调色板打开插件）。若终端配置仍把 **Clear**（或其他命令）绑到 `Ctrl+L`，宿主可能抢走该组合 —— 请重绑或移除，使 PTY 收到 form feed（`\x0c`）。

## 全局

任意屏幕可用的操作。

| 键 | 替代键 | 操作 | 确认 |
|----|--------|------|------|
| `Ctrl+N` | | 新建会话（可选在 git worktree 中） | 是（1000ms 内双按） |
| `Ctrl+Q` | `Ctrl+D` | 退出应用 | 是（1000ms 内双按） |

**VS Code 家族终端**（VS Code、Cursor、Windsurf、Zed 集成终端）：`Ctrl+Q` 被宿主捕获，因此 Grok 让 **`Ctrl+D` 成为唯一退出键**（`Ctrl+Q` 不绑定）。半页下滚改为裸 **`Shift+D`**。回合中途插话用 **`Ctrl+L`**（无替代），因为 `Ctrl+Enter` / `Ctrl+I` 不一定能到达 PTY；扩展通过 `/plugins` 打开而不是 `Ctrl+L`。

> **返回欢迎屏没有按键绑定** —— 在会话中使用 `/home` 斜杠命令（别名 `/welcome`）。见 [斜杠命令](04-slash-commands.md)。

### 破坏性操作确认

确认列为「是」的操作需要 1000ms 内双按。先按一次看到确认提示，再按一次确认。防止误丢会话。

## 欢迎屏

仅在欢迎屏生效的绑定（尚未打开任何智能体会话）。

| 键 | 操作 |
|----|------|
| `Ctrl+S` | 恢复会话（打开会话选择器） |
| `Ctrl+W` | 打开 New Worktree 对话框（仅在 git 仓库内） |
| `Ctrl+I` | 导入 Claude 设置（可用时） |
| `Ctrl+Shift+I` | 关闭 Claude 导入行（可用时） |

`Ctrl+W`、`Ctrl+I` 与 `Ctrl+Shift+I` 仅在欢迎屏激活。`Ctrl+S` 在欢迎屏与智能体会话内都打开会话选择器（会话内为模态浮层，等同 `/resume`）。`Ctrl+Q` 是上文全局退出绑定，不是欢迎屏专用处理。

## 命令调色板

按 `Ctrl+P` 或 `?` 打开命令调色板 —— 可搜索的操作列表。调色板显示：

- 所有键盘快捷键及其当前绑定
- 所有斜杠命令
- 可用技能

输入过滤，按 `Enter` 执行选中操作。

## 快捷键栏

TUI 底部显示上下文快捷键栏，展示当前状态最相关的绑定。提示会随以下变化：

- 哪个窗格聚焦（回滚 vs 提示）
- 智能体是否正在运行
- 选中条目的类型

## 鼠标支持

TUI 支持鼠标交互：

- **点击** 回滚条目以选中
- **滚轮** 滚动回滚区
- **点击** 提示区以聚焦
- **悬停** 提示区可见高亮（可通过 `pager.toml` 配置）
- **中键** 在 Linux X11/XWayland 上粘贴 PRIMARY 选择

粘贴图片：        Alt+V（仅 Windows —— 截图 /「复制图片」）
全选：            Cmd+A（仅 macOS Ghostty —— 见下方说明）
离开：            Tab（回到回滚）
取消（运行中）：  Ctrl+C（空提示；非空草稿先清空）
清空（空闲）：    800ms 内 Esc Esc（非空提示）
回溯（空闲）：    800ms 内 Esc Esc（空提示 + 有消息）
```

> **Cmd+A 仅对 Ghostty 启用。** Grok 应用内 `Cmd+A` 处理
> 仅在检测到终端为 Ghostty 时接线。其他终端
> 要么在终端层吞掉 `Cmd+A`（Apple Terminal、默认 iTerm2），
> 要么应用自己的终端内「全选」（Kitty、WezTerm）。
> 非 Ghostty 终端上该绑定无效，按键落到终端原生行为。
>
> 在 Ghostty 中，向 `~/.config/ghostty/config` 加一行解绑，
> 使按键到达运行中的 TUI：
>
> ```ini
> keybind = cmd+a=unbind
> ```
>
> Ghostty 重载配置后（会监视配置文件），提示区中的 `Cmd+A`
> 会选中提示缓冲区中的每个字符，包括粘贴的图片芯片。
> 图片芯片始终无路径（`[Image #N]`）；文件路径（若已知）
> 仅在悬停预览浮层或光标在芯片上/紧邻右侧时出现。
